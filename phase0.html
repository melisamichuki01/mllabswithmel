01 The Terminal ✓Mark done

🔁 In plain life terms...

The terminal is like texting your computer instead of clicking on it. Instead of using your mouse to open folders and apps, you type short commands and your computer does exactly what you said. It sounds harder, but once it clicks, it's actually faster and more powerful than anything you can do with a mouse.

Every professional developer uses the terminal every single day. You're going to start using it on day one.

Opening the terminal on Windows

Windows has a few terminal options. The best one to use for this course is Command Prompt or PowerShell. Here's how to open either one:

1

Press the Windows key

The Windows key is between Ctrl and Alt on the bottom left of your keyboard. It has the Windows logo on it.

2

Type "cmd" or "PowerShell"

Start typing immediately — you don't need to click anywhere first. Either works. PowerShell is slightly more powerful; cmd is simpler. Start with cmd if you're not sure.

3

Press Enter

A black (or blue) window opens with a blinking cursor. That's your terminal. It's waiting for you to type something.

🚨 Don't worry — this window looks scary at first

The terminal is just a text interface. You type, press Enter, and something happens. That's it. You cannot break your computer just by typing commands — the worst that happens is you get an error message, and error messages are just the terminal telling you what went wrong so you can fix it.

The commands you actually need to know

You don't need to memorise hundreds of commands. Here are the five that matter right now:

CommandWhat it doesExample
cd foldernameMove into a folder (cd = change directory)cd Documents
cd ..Go back up one folder levelcd ..
dirList what's inside the current folderdir
mkdir foldernameCreate a new foldermkdir my_project
python --versionCheck if Python is installed and which versionpython --version
🟢 Try these in your terminal right now
# Check where you are right now
cd

# Move into your Documents folder
cd Documents

# See what's inside
dir

# Create a folder for this course
mkdir mllabs

# Move into it
cd mllabs

# Confirm you're in the right place
cd
💡 What does a "path" mean?

A path is just the address of a file or folder on your computer. C:\Users\YourName\Documents\mllabs is a path — it tells your computer exactly where to find that folder, floor by floor, like a building address.

When you type cd in the terminal, it shows you your current path — where you are right now in the building.

🎯 Mini Challenge — The Terminal

Using only the terminal (no mouse, no File Explorer):

1. Navigate to your Desktop.
2. Create a new folder called python_practice.
3. Move into that folder.
4. Confirm you're in the right place by checking your current path.

The last cd on its own prints your current location. It should end with \Desktop\python_practice.

You now know how to navigate your computer with text commands. This is a skill most people never bother to learn — you just did it on day one.

02 Setting Up with Anaconda ✓Mark done

🔁 Here's the everyday version of that

Installing Python on its own is like moving into a new flat with bare walls and no furniture. You can live there, but you'll spend weeks sourcing everything separately. Anaconda is the furnished flat — Python is already there, plus all the data science tools you'll need (Pandas, NumPy, Jupyter, and more) come pre-installed and configured properly.

It also handles environments — which means different projects can use different versions of Python and different libraries without clashing with each other. This matters more than it sounds, and you'll thank yourself later for starting with Anaconda.

Installing Anaconda

1

Go to anaconda.com/download

Click the big Download button. It will detect Windows automatically and download the right installer. The file is about 800MB — it takes a few minutes.

2

Run the installer

Double-click the downloaded .exe file. Click through the setup. When it asks "Install for Just Me" or "All Users" — choose Just Me. This avoids permission problems later.

3

Leave the PATH option unchecked

The installer will ask if you want to "Add Anaconda3 to my PATH environment variable". Leave this unchecked. It's checked by default in some versions — make sure it isn't. You'll use Anaconda Prompt instead, which handles this for you.

4

Finish the installation

Click Finish. The installation is done. You do not need to register or create an Anaconda account.

On a Mac? Download the macOS installer from the same page. The setup is nearly identical. The terminal commands in this course work on Mac too — just use ls instead of dir.

Verifying the installation

Open Anaconda Prompt — not your regular terminal. Search for "Anaconda Prompt" in your Start menu. It looks like a regular terminal but has Anaconda's environment activated automatically.

🟢 Run in Anaconda Prompt
# Check that Python is there
python --version

# Check that conda (the environment manager) is there
conda --version

# See all the packages that came pre-installed
conda list
Expected output (your exact version numbers may differ)
Python 3.11.5
conda 23.7.4
🚨 If you see "conda is not recognised" in regular cmd

This is normal. Anaconda creates its own terminal called Anaconda Prompt — use that instead of regular Command Prompt for everything in this course. Search "Anaconda Prompt" in your Start menu. It should be there after installation.

Creating your first environment

An environment is like a fresh, clean room for a specific project. The packages you install inside one environment don't affect any other. This is the professional way to work.

🟢 Run in Anaconda Prompt
# Create an environment called "mllabs" with Python 3.11
conda create --name mllabs python=3.11

# It will ask you to confirm — type y and press Enter
# This takes a minute or two

# Activate the environment (switch into it)
conda activate mllabs

# Your prompt now shows (mllabs) at the start — you're inside it

# Check you're using the right Python
python --version
💡 Why bother with environments at all?

Imagine two projects: one needs Pandas version 1.5, and another needs version 2.0. If you install everything in the same place, they fight over which version is installed, and one of them breaks.

Environments keep them separate. Project A lives in its own room with its own furniture. Project B lives in a different room with different furniture. They never see each other.

For now, your mllabs environment is where you'll do all your work for this course. Always activate it before you start coding.

Installing the key packages

With your mllabs environment activated, install the libraries you'll need for this course:

🟢 Run in Anaconda Prompt (with mllabs activated)
# Install the core data science stack in one command
conda install pandas numpy matplotlib seaborn jupyter

# Type y when it asks to confirm
# This will take a few minutes — Anaconda is downloading and setting up

# Verify pandas installed correctly
python -c "import pandas; print(pandas.__version__)"
🎯 Mini Challenge — Anaconda

Open Anaconda Prompt and complete the following:

1. Activate your mllabs environment.
2. Check which Python version is active — it should say 3.11.x.
3. Run this one-liner in the terminal to confirm Pandas is installed and print its version.

If the last command prints a version number (like 2.1.0) without any error, Pandas is installed and working correctly.

Anaconda is installed, your environment is set up, and the key packages are ready. You have a proper Python development environment — the same foundation professional data scientists use.

03 VS Code and Extensions ✓Mark done

🔁 Think of it like this...

You could write Python code in Notepad — it would technically work. But that would be like writing a novel with a pencil stub on a napkin. VS Code is a proper word processor for code. It colours your code so errors stand out, it spots mistakes before you run anything, it lets you see your files, run the terminal, and debug — all in one window.

It's free, it's fast, and it's what most professional Python developers actually use.

Installing VS Code

1

Go to code.visualstudio.com

Click the big blue Download button. It will detect Windows and download the right installer automatically.

2

Run the installer

Accept the agreement. When you reach "Select Additional Tasks", tick "Add to PATH" and "Open with Code" context menu options. Leave everything else as default.

3

Open VS Code

VS Code opens automatically when installation finishes. You'll see a welcome screen. You can close that tab.

Installing the extensions you need

VS Code is lean by default. Extensions are what give it superpowers for Python. You need exactly three:

ExtensionWhat it doesPublisher
PythonThe core Python support — syntax highlighting, running scripts, selecting your interpreterMicrosoft
PylanceSmarter autocomplete, real-time error detection as you type, type hintsMicrosoft
JupyterLets you run .ipynb notebook files directly inside VS CodeMicrosoft
1

Open the Extensions panel

Click the square icon on the left sidebar (it looks like four squares, one slightly detached). Or press Ctrl + Shift + X.

2

Search for "Python"

The first result should be the Python extension by Microsoft. Click Install. Pylance usually installs alongside it automatically.

3

Search for "Jupyter"

Install the Jupyter extension by Microsoft. This gives you notebook support inside VS Code.

Selecting your Python interpreter

VS Code needs to know which Python to use. You have Anaconda installed with a mllabs environment — point VS Code at that one.

1

Press Ctrl + Shift + P

This opens the Command Palette — VS Code's search bar for every feature and setting.

2

Type "Python: Select Interpreter"

Click that option when it appears in the dropdown.

3

Choose the mllabs environment

You'll see a list of available Python installations. Find the one that says conda: mllabs or shows a path containing mllabs. Click it.

The path you're looking for will look something like this
Python 3.11.5 ('mllabs': conda)
~\anaconda3\envs\mllabs\python.exe
🚨 I don't see my mllabs environment in the list

This sometimes happens when VS Code opens before Anaconda has fully set up. Try two things: first, close VS Code and reopen it. Second, in your Anaconda Prompt with mllabs activated, type code . and press Enter — this opens VS Code from within the activated environment, and it should recognise it immediately.

Opening a folder (the right way)

Always open a folder in VS Code, not a file. This gives VS Code context about your project — where your files are, how they relate, and where the terminal should start.

1

File → Open Folder

Or press Ctrl + K, Ctrl + O. Navigate to your mllabs folder in Documents (or wherever you created it).

2

Click "Select Folder"

VS Code opens that folder as your workspace. You'll see the folder contents in the left sidebar.

3

Open the integrated terminal

Press Ctrl + ` (the backtick key, usually top-left of your keyboard). A terminal opens at the bottom of VS Code, already pointed at your folder.

Good habit to build now: always open VS Code by opening a folder, not by double-clicking a file. It keeps your workspace organised and your terminal in the right place.

VS Code is set up and talking to your Anaconda environment. You have a proper coding workspace.

04 Jupyter Notebooks in VS Code ✓Mark done

🔁 Real world version

A Jupyter Notebook is like a laboratory notebook — the kind scientists use to write down an experiment, run it, record the result, add notes, and then run the next experiment. Each block (called a cell) can contain code or notes. You run one cell at a time, and the output appears directly below it. This makes it perfect for exploring data: you can try something, see the result immediately, adjust, and try again.

Creating your first notebook

1

Open the Command Palette

Press Ctrl + Shift + P inside VS Code.

2

Type "Jupyter: Create New Jupyter Notebook"

Select it from the list. A new .ipynb file opens with one empty cell.

3

Select the kernel

In the top right corner of the notebook, you'll see "Select Kernel". Click it and choose Python 3.11 (mllabs) or whichever matches your conda environment.

4

Save the notebook

Press Ctrl + S. Name it phase0_test.ipynb. It saves into your mllabs folder.

Running your first cell

🟡 Type this in the first cell of your notebook
print("Hello from my first notebook!")
print("Python is running and the environment is working.")

Press Shift + Enter to run the cell. The output appears directly below it. If you see the two print statements, everything is working.

💡 What's a kernel and why does it matter?

The kernel is the engine running your notebook. When you run a cell, the kernel executes the code and sends the result back to the screen. The kernel also remembers what you've done — so if you define a variable in cell 1, cell 5 can still use it.

If your notebook starts behaving weirdly (variables seem to disappear or give unexpected values), the fix is almost always to restart the kernel: go to the Kernel menu and click "Restart". This wipes the memory and starts fresh.

The difference between notebooks and scripts

.ipynb Notebook.py Script
How you run itOne cell at a time with Shift+EnterAll at once from the terminal
Output appearsInline, right below the cellIn the terminal
Best forExploring data, experimenting, learningBuilding tools, automations, applications
VariablesShared across all cells while kernel runsRun once and gone
In this courseUsed for data exploration phasesUsed for everything you build
Quick rule: when you're figuring something out — use a notebook. When you're building something that needs to run on its own — write a script. Most data scientists use both, switching between them depending on what they're doing.
🎯 Mini Challenge — Jupyter

In your phase0_test.ipynb notebook:

1. In cell 1, import pandas and print its version.
2. In cell 2, create a variable called my_name with your name as a string.
3. In cell 3, use that variable in a print statement — prove that cell 3 can "remember" what was set in cell 2.

🟡 Cell 1
import pandas as pd
print(f"Pandas version: {pd.__version__}")
🟡 Cell 2
my_name = "Mel"  # put your actual name here
🟡 Cell 3
print(f"Hello, {my_name}. Your environment is fully set up.")

Cell 3 works because the kernel is keeping track of my_name since it was defined. This is the shared memory that makes notebooks so useful for exploration.

You're running Jupyter notebooks directly in VS Code with your Anaconda environment. That's the setup that professional data scientists use every day.

06 Common Errors and Fixes ✓Mark done

These are the errors that trip up almost everyone during setup. If something goes wrong, check here first before anything else.

ErrorWhat it meansFix
'python' is not recognizedPython is not on your PATH, or you're using regular cmd instead of Anaconda PromptOpen Anaconda Prompt instead of regular cmd. Run conda activate mllabs first.
'conda' is not recognizedSame issue — regular cmd doesn't know about condaAlways use Anaconda Prompt for anything related to Python or conda
VS Code doesn't show mllabs interpreterVS Code can't find the conda environmentClose VS Code. Open Anaconda Prompt, run conda activate mllabs, then type code . to open VS Code from within the environment
ModuleNotFoundError: No module named 'pandas'You're running Python from the wrong environmentActivate mllabs first: conda activate mllabs. Then run your script again.
Notebook kernel won't startThe Jupyter extension can't connect to your environmentSelect the kernel manually: top-right of the notebook, click "Select Kernel", choose the mllabs conda environment
SyntaxError: invalid syntaxThere's a typo in your code — a missing colon, bracket, or quoteRead the error message — it tells you the exact line number. Look at that line carefully.
The golden rule of setup errors: if something isn't working, the first thing to check is whether you're in the right environment. Run conda activate mllabs, then try again. Nine times out of ten, that's the fix.
