01 What is a Jupyter notebook? ✓Mark done

🔁 Think of a scientist's laboratory notebook

A scientist's lab notebook doesn't just have results. It has the experiment, the setup, the results, the notes about what went wrong, and a sketch of what to try next — all in one place, in order.

A Jupyter notebook works the same way. Each block (called a cell) can contain code or notes. You run one cell at a time. The output appears right below it. You can go back, change something, and run it again. You can add text between cells to explain what you're doing and why.

This makes notebooks perfect for data work: you can try something, see the result, understand what happened, and adjust — all without leaving the page.

Jupyter notebooks are saved as .ipynb files — that stands for "Interactive Python Notebook". They're the standard format in data science, used everywhere from university courses to Google and NASA. You'll use them throughout Track A of this course for all data exploration work.

02 Creating your first notebook in VS Code ✓Mark done

You installed the Jupyter extension in Lesson 0.3. VS Code can now open, create, and run .ipynb files directly — no browser, no separate Jupyter server.

1

Open the Command Palette

Press Ctrl + Shift + P.

2

Create a new notebook

Type "Jupyter: Create New Jupyter Notebook" and select it. A new .ipynb file opens with one empty code cell.

3

Select the kernel

In the top right of the notebook, click "Select Kernel". Choose the option that matches your mllabs conda environment — it will say something like Python 3.11.5 (mllabs).

4

Save it

Press Ctrl + S. Name it my_first_notebook.ipynb. It saves into your current workspace folder.

🚨 I don't see the mllabs kernel in the list

When you installed packages in lesson 0.2, you should have included ipykernel. If the mllabs kernel isn't showing up, try this: open Anaconda Prompt, activate mllabs, and run python -m ipykernel install --user --name mllabs --display-name "Python (mllabs)". Then restart VS Code and try selecting the kernel again.

03 Cells, markdown, and the kernel ✓Mark done

Cell types

Every notebook is made up of cells. There are two types you need to know:

Cell typeWhat it containsHow to run it
Code cellPython code. When you run it, the output appears directly below.Shift + Enter, or click the ▶ button
Markdown cellFormatted text: headings, bold, bullet points, links. Good for notes and explanations.Shift + Enter renders the formatting

To switch a cell type: click the cell, then look at the cell type dropdown in the top-right area of the cell (it says "Code" or "Markdown"). Click it to switch.

The kernel — what it is and why it matters

💡 Here's what's going on under the hood

The kernel is the engine running your notebook. When you run a cell, VS Code sends your code to the kernel, the kernel executes it, and sends the result back to display below the cell.

The kernel also has memory. If you define a variable in cell 1, cell 5 can still use it — because the kernel remembers everything that's been run in this session. This shared memory is what makes notebooks so powerful for exploration.

When things go wrong: if a variable gives unexpected results, or something is behaving strangely, the fix is almost always to restart the kernel: go to the Kernel menu at the top and click "Restart". This wipes the memory and starts fresh. Then run your cells in order from the top.

04 Notebook vs script: when to use each ✓Mark done

Quick rule: if you're figuring something out, use a notebook. If you're building something, write a script. Most data scientists use both, switching between them depending on what they're doing. You'll do the same.

06 Practice tasks ✓Mark done

Task 01 — Easy

In a notebook, write three cells. Cell 1: define two numbers. Cell 2: add them. Cell 3: multiply them. Run them in order. Then change cell 1's numbers and run all three again — notice how cells 2 and 3 update.

Task 02 — Easy

Add a Markdown cell to your notebook. Write a heading, some bold text, and a bullet list. Run the cell to see it render. Edit the markdown and run again. This is how you annotate your work in data science.

Task 03 — Medium

Run your cells out of order on purpose — run cell 3 before cell 2, or cell 2 before cell 1. Notice what happens. Then restart the kernel and run everything in order. This teaches you why cell order matters and why "Restart and Run All" is such an important button.

Task 04 — Challenge

Write a notebook that demonstrates the kernel memory in a breaking scenario: define a variable, restart the kernel without running that cell, then try to use the variable in a later cell. Document what error appears and why with a Markdown cell explaining the cause.
